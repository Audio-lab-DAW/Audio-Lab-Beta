### Built
- **Safe mode** starts AudioLab as it came and deletes nothing. Three doors: the logo menu, **Restart › Restart in safe mode…** (it asks first and says nothing is deleted; the command `help.safeMode`); **holding Shift while AudioLab starts** (a Shift key, or a click or move with Shift, before the first frame and 1.5 s after it: a small bar asks, so a stray Shift never restarts anything); and **offered by itself after a start that did not finish** (a mark written where the settings are read at start, removed at the first frame and when the page closes normally; still there at the next start means that start died). The offer is a bar at the top, never a dialog, so a start that may be broken is not blocked.
- **What safe mode sets aside** (`XT_SAFE.K`, 88 keys): every setting of the settings table, the Workshop's own values (`UI.xtSet` and the keys it opened), keyboard shortcuts, and the four layout systems (transport bar order, size and hidden parts; track header controls; mixer view options; hidden device panel parts). They start at the built-in defaults (`XT_UI0`, a copy taken just before the stored settings are read). **Light mode stays as it is**: it protects a slow computer, and safe mode must never make AudioLab heavier. Projects are never touched.
- **Nothing is deleted**: in safe mode `UI.toJSON` writes the stored customisations back on every save, so a change made in safe mode to one of them is not kept and everything returns when you leave. Other remembered choices (window sizes, last used options) save as usual. Safe mode lasts until you leave it or quit (sessionStorage).
- **The bar of safe mode**, across the top: "AudioLab started as it came. N customisations are set aside, not deleted: they come back when you leave." with **What is changed** and **Leave safe mode** (asks, restarts with everything back); click the badge to fold it.
- **What is changed**, a second tab of the Workshop (command `view.whatIsChanged`): one list across every kind, grouped Settings, Keyboard shortcuts, Layout, each with what it is now and its default, and its own **✕** (settings through the Workshop list's reset, so Settings' own handler runs; shortcuts and layout put back at once and redrawn). Glass rows show ↗ to Settings. In safe mode it lists what is set aside (taken when safe mode was entered, while the controls still showed it), without ✕.
- **Reset my customisations…** asks first, keeps a dated backup (Settings › General's backups, `ST7.backup('before Reset my customisations')`), puts every customisation back to its default and restarts. **Bring them back** in the same tab undoes it from that backup.
- Hooks for other lanes: `XT_HOOKS.safeMode()` (true in safe mode: a lane with its own customisation should start as it came then), `XT_HOOKS.whatIsChanged()`.
- Code: two lines next to where the stored settings are read at start (`XT_UI0`, `XT_SAFE`; `taskXT_DL4_early.js`), block "SAFE MODE, WHAT IS CHANGED, RESET (v0.000, task XT-DL4)" before `askChoice`, CSS before `.dacv`, one entry in the logo menu's Restart submenu; edit script `tools/edits/taskXT_DL4.py`. Names use the lane's `xt` prefix.
- Known limits: Settings' own "Reset all settings" and "Restore" used while in safe mode do not reach the set-aside customisations (they come back on leaving); a second AudioLab tab started at the same moment in the browser version can show the offer once.
