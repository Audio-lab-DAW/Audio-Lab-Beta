## 28 November 2026, v0.000: task XT-DL5, UI rules: hide and rename a control, the right-click Advanced entries (extensions and the Workshop, lane H, sixth step)
Row DL5 of docs/extensions-plan.md 9.7 (9.6 b; the user's pick K12a with their note). Depends on DL1 (logged, v0.266); built on DL4 (its What is changed tab and safe mode). Built and tested on v0.314 with DL4 applied, during the release gate's freeze of 28 November (17:28 UTC); goes out with `tools/edits/taskXT_DL5.py` and `taskXT_DL5_release.py` after DL4.

### Built
- **Right-click entries that name the control** (K12a and the user's note): right-click a control of the transport bar, the track headers or the mixer and the menu ends with the amber **◇ Advanced** group: **Hide the Loop button** and **Customise the Loop button…** (the control's own name from CONTROLS, never "Hide this"). A control with a menu of its own keeps it and gets the group last (Play, the track menu); a control with none gets a small menu with only the group. Each entry's tooltip starts with "Advanced:" and says what happens (where it disappears from, "on every track" for a repeated control, that its key and command still work, where to bring it back).
- **The first use explains**: the first Hide or Customise opens a question titled "Advanced: hide the Loop button?" that says this is an advanced customisation, what disappears, that its shortcut and command keep working, and how to bring it back (the AudioLab menu › Workshop… › What is changed › ✕, or safe mode with Shift at start). After that a hide is done at once with a line at the bottom ("Workshop › What is changed brings it back").
- **Customise…**: "Advanced: customise the Loop button" with Rename… (24 characters at most, plain text), Hide it or Show it again, Put it back as it came.
- **The rules** (`UI.xtRules`, the `ui-rules.json` format of 9.6 b: `{audiolab:'ui-rules',version:1,layouts:{all:[{id,hide,rename}]}}`) by the stable ids of DL1; a rule on a repeated control covers every track or channel; later rules win. Hide is one small stylesheet (`#xtRulesCss`, `[data-al="id"]{display:none}`), made only while a rule hides something; hidden is not gone (its command and key still work). Rename sets the words where the control shows plain text, its tooltip ("New name: old tooltip") and its spoken name; removing it gives the control its own words back; renames are put back after an area is rebuilt (inside DL1's id pass).
- **Protected** (`XT_RULE_PROTECT`): the AudioLab menu button, Record, the master meter, peak and loudness boxes, the clip warning, the performance meter, the mixer's Close and the master faders cannot be hidden; their Hide entry is off and says why. The same check (`xtRuleCheck`) refuses it in a rule.
- **A bad rule changes nothing and is kept**: an unknown id (a newer AudioLab, a typo) or a bad value is kept and ignored, and What is changed lists it as "not used" with the reason.
- **Undo everywhere**: every rule is a row of What is changed (Layout, "a control rule", ✕ removes it); Reset my customisations and safe mode cover the key `xtRules` (safe mode starts with no rules and deletes none).
- **For lane F (OV3)**: `XT_HOOKS.rules.items(control)` gives the Advanced group's entries for a control (`xtControlOf(el)`); set `OV_HOOKS.xtAdvanced=true` when your menus add them and this step's wrapper of `openMenu` stops adding them. Also `XT_HOOKS.rules.set(id,{hide,rename})`, `.of`, `.check`, `.hidden(id)`, `.protected(id)`.
- **Not done in this step**: the plan's "today's four small systems (`trHide`, `hcz`, `mxOpt`, `fxHide`) store through it". They belong to lanes A, E, I and the mixer lanes (CLAUDE.md: never rewrite another lane's code); they stay as they are, are already listed and reset by What is changed (DL4), and a lane that wants its hide state in the rules file can call `XT_HOOKS.rules.set`. Moving controls, per layout, the picker and the file view are DL6.
- Code: block "UI RULES: HIDE AND RENAME A CONTROL (v0.000, task XT-DL5)" before `askChoice`; edit script `tools/edits/taskXT_DL5.py` with `taskXT_DL5_block.js`. No CSS. Names use the lane's `xt` prefix.
