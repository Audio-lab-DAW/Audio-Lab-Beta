## 27 November 2026, v0.295: task XT-DL3, the advanced settings list (extensions and the Workshop, lane H, fourth step)

Built and tested on v0.294 during the release freeze of 27 November (22:26 UTC); `index.html` waited for the gate, as CLAUDE.md says, and was released by the next XT run with `tools/edits/taskXT_DL3.py` and `taskXT_DL3_release.py`.

### Built
- **The Workshop window** (the user's picks K2b its own window, K3a "Workshop", K4a always in the menu): right-click the logo, **Workshop…** ("advanced: every setting by its id"), or the command `view.workshop`. A purple **Advanced** mark in its title bar; the first time, a note says it is an advanced feature, what the marks mean and that ↺ on a row puts a change back ("Got it" hides it for good, `UI.xtWsSeen`). DL3 has one tab, "Settings list"; DL10 adds the others.
- **The list**: every setting by a stable id, with a plain sentence, its default, its range, marks (no control, elsewhere, locked, in Settings, project, not kept, changed), an editor of the right kind, ↺ when changed and ↗ "show in Settings". Search over id, name, help line and the table's synonyms ("latency" finds `audio.buffer`). Filters All, Changed, Not in Settings, Locked. On the right, "What is kept": only what differs from the default, yours and the project's (the files themselves come with DL9).
- **Where the rows come from**: the 102 rows of the settings table `STT` (without its second controls), changed through `SETT.set`, so the Settings window's own handler runs and nothing is written twice; the glass chain's rows and the list rows are shown, changed only in Settings. Then `XT_SET_OWN`: three values with no control anywhere (`edit.undoSteps` 80, opened from a constant; `performance.frozenMemoryMB` 384, `UI.bgfMB`, which had no control; `workshop.consoleLines` 50), five set elsewhere by a menu or a drag (Capture's phrase gap and longest phrase, count-in bars, the Map's height, the velocity lane's height), and four locked values shown read-only with the reason (the script sandbox's time limit, log lines, changes and code size, read from `XT_SBX`).
- **Ids**: `XT_SET_NS` names each `STT` row once as page.id (the pages as Settings shows them today, after S5); a row that later moves keeps its id. Listed in **`docs/settings-ids.md`**; a released id is never renamed or reused. A new `STT` row without a name shows as `settings.<id>` and the test asks for a row in both.
- **Storage**: a value with no key of its own lives in `UI.xtSet`, differences only; with nothing changed it does not exist. Values are checked (a number, the range); a refused value changes nothing and the row says why ("Between 20 and 400 steps.").
- **Opened constants**: Undo's depth (`pushUndo` and the preset browser's change, both old core code: `if(UNDO.length>80)` became `while(UNDO.length>xtV('edit.undoSteps',80))`), the run log's length (lane H). The rest of 9.6 a's list (tooltip delay, double-click time, drag threshold, meter rate, voice limit, wheel zoom step) sits in other lanes' code: each lane can open one with `XT_HOOKS.val(id, default)` and a row in `XT_SET_OWN` (ask lane H). `XT_HOOKS.openWorkshop()` is there for lane B's link at the foot of Settings (9.6 f).
- **Settings' controls show stored values only after Settings has opened once** (its pages are built and filled on open). The first time the Workshop opens in a session it opens and closes Settings in the same task (never drawn), so the list reads the right values.
- **The ids registry kept up with other lanes**: three mixer controls added since DL1 had no id (lane K MX-1's pre/post ring and Output button, lane D's Loss button): now `mixer.strip.sendPrePost`, `mixer.strip.output`, `mixer.master.monoLoss` in `CONTROLS` and `docs/ids.md`; lane D's `ni.monoLoss` command got its row in `docs/commands.md`. `taskXT_DL1.py` and `taskXT_DL2.py` pass again.
- Code: block "ADVANCED SETTINGS LIST (v0.295, task XT-DL3)" before `askChoice`, CSS before `.dacv`, one menu entry in the logo menu, edit script `tools/edits/taskXT_DL3.py` with `taskXT_DL3_block.js`, `taskXT_DL3_css.txt`, `taskXT_DL3_ns.json`. Names use the lane's `xt` prefix.
